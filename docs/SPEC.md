# Mind Mirror 참여자 앱 SPEC

출처: 「K-OASIS 이미지 재구축 및 Mind-Mirror Prototype App 디자인 개발용역 완료보고서」(2026.10.19, 키네스트 → 강원대학교 원주산학협력단) 와 시안 18장.

## 1. 목적

- OASIS(Open Affective Standardized Image Set)를 한국 청소년에 맞게 재구축한 K-OASIS 이미지를 보여주고, 이미지별 정서 반응을 수집하는 심리테스트 앱.
- 이번 범위: **조사 참여자용 모바일 화면**. 전문가 분석 화면과 델파이 분석은 후속 과제.
- 대상: 청소년 주력. 개인정보와 얼굴 영상 처리에 주의한다.

## 2. 화면 흐름

| # | 라우트 | 화면 | 시안 |
|---|---|---|---|
| 1 | `/` | 스플래시 (로고 → "by K-OASIS Image Pool" → 시작 안내) | 0, 0-2, 1 |
| 2 | `/info` | 1단계: 참여자 정보 입력 | 2 |
| 3 | `/consent` | 2단계: 카메라 동의 | 3 |
| 4 | `/mood/pre` | 3단계: 사전 무드미터 (감정 격자) | 4 |
| 5 | `/ready` | 조사 시작 안내 | 5 |
| 6 | `/test` | 본조사 (이미지 N장 반복) | 6 v2 (Type 2) |
| 7 | `/done` | 조사 완료 안내 | 7 |
| 8 | `/mood/post` | 사후 무드미터 (감정 격자) | 8 v1 |
| 9 | `/loading` | 결과 도출 로딩 | 9 |
| 10 | `/result` | 간략 결과지 | 10 |

확정된 선택: 본조사는 **Type 2**(캐릭터 얼굴 척도), 무드미터는 **격자형**(사전, 사후 동일 컴포넌트). 사분면+세부 감정(8-1, 8-2) 시안과 Type 1은 사용하지 않는다.

## 3. 화면별 요구사항

### 3.1 스플래시 `/`
- 검정 배경에 보라·파랑 글로우. 로고와 "Mind Mirror" 워드마크
- 1단계: 로고만 → 2단계: "by K-OASIS Image Pool", 하단 "©강원대학교 원주산학협력단" → 3단계: "마음을 보는 거울 마인드 미러 / 지금 내 마음을 알아볼까요?" + `시작하기` 버튼
- 1, 2단계는 시간 경과로 자동 전환 (전환 시간 임의 설정, 설정값으로 분리)

### 3.2 정보 입력 `/info` (1단계)
- 상단 헤더(로고, 메뉴 아이콘), 단계 표시 1-2-3
- 안내: 입력한 개인정보는 비식별화 프로그램(De-identification)을 통해 익명으로 저장
- 필드: 이름(텍스트), 생년월일(8자리 숫자), 성별(셀렉트), 직업(텍스트), 지역(셀렉트)
- `제출하기` 버튼. 필수값 검증 후 활성화
- 성별·지역 선택지 목록은 미확정 (지역은 시도 단위로 임시 구성)

### 3.3 카메라 동의 `/consent` (2단계)
- 문구: 카메라를 켜면 조사 중 표정 변화를 기록, 분석한다
- 체크박스 `이용약관에 동의합니다`, 버튼 `내 표정 분석하기`
- "꼭 기록하지 않아도 괜찮아요." 영역에 `오늘은 조사만 하기` 버튼 (동의 없이 진행 가능)
- **1차 범위(a안)**: 동의 여부만 세션에 저장한다. 카메라는 켜지 않는다
- 이용약관 문구는 임시 텍스트로 시작

### 3.4 사전 무드미터 `/mood/pre` (3단계)
- 6x6 감정 격자에서 오늘의 기분 한 칸 선택. 선택 후 `제출하기`
- 격자 데이터는 아래 4절 참고

### 3.5 준비 `/ready`
- "자 그럼 마음을 보는 거울 마인드 미러를 시작합니다!"
- "화면에 나오는 사진을 보고, 처음 느껴지는 기분을 7단계 중에서 선택해 주세요."
- `시작하기`

### 3.6 본조사 `/test`
- 상단: "테스트 진행률 N%" + 그라데이션 진행 바
- "다음 사진을 보고 처음 느껴지는 기분을 선택해주세요."
- 이미지 (모서리 둥근 카드)
- 질문 1 "어떤 기분이 드나요?": 7단계 얼굴 아이콘, 좌 `불쾌함` ~ 우 `유쾌함` (값 1~7)
- 질문 2 "얼마나 자극적으로 느껴지시나요?": 7단계 얼굴 아이콘, 좌 `자극적` ~ 우 `평온한` (값 1~7)
- 두 질문 모두 선택해야 `다음 사진` 활성화. 마지막 장에서는 `/done`으로 이동
- 이미지 수와 선택 방식은 `surveyConfig`에서 읽는다 (임시: 20장 랜덤)
- 이미지별 응답 시간(ms)을 함께 기록한다
- K-OASIS 파일 확보 전에는 임시 이미지(플레이스홀더)로 개발한다. 파일명과 순서는 원본 OASIS와 동일하다

### 3.7 완료 `/done`
- "수고하셨습니다. 모든 조사를 마쳤습니다." / "작성해 주신 내용으로 마음의 거울을 준비해 볼게요." / `계속하기`

### 3.8 사후 무드미터 `/mood/post`
- 제목 "테스트를 마친 지금, 기분이 어떤가요?" / "조사 전과 비교해 기분이 어떻게 달라졌는지 선택해 주세요."
- 6x6 격자 선택 → 하단 "내가 선택한 오늘의 기분은 '○○'이에요." + `감정 기록하기`

### 3.9 로딩 `/loading`
- 스피너, "테스트 결과 도출 중..." / "테스트 결과를 준비 중이에요. 조금만 기다려주세요."
- 결과 저장 완료 후 `/result`로 이동

### 3.10 결과지 `/result`
- "○○ 님의 테스트 결과" / "마인드미러로 들여다본 오늘 내 마음의 상태는 이렇습니다."
- 시안에는 상태 문구 3종(약간의 우울함이 느껴지는 날, 화가 나는 날, 마음이 지친 날)과 마무리 문구가 나란히 있다. **어떤 조건에 어떤 문구를 보여줄지 기준은 미확정**
- 버튼: `공유하기`(Web Share API), `이미지로 저장하기`(결과 영역 캡처)
- 산출 규칙 확정 전까지는 문구 데이터를 `src/constants`로 분리하고, 임시로 사후 격자의 사분면에 매핑한다

### 3.11 공통
- 헤더: 좌측 로고 + "Mind Mirror", 우측 메뉴 아이콘 (메뉴 내용 미정, 1차는 비활성)
- PWA: 홈 화면 아이콘, standalone, 세로 고정, 안전 영역(safe-area) 처리
- 접근성: 척도 버튼에 `aria-label`(예: "불쾌함 3단계"), 터치 영역 44px 이상

## 4. 감정 격자 데이터 (6x6)

행 1~3은 에너지 높음, 행 4~6은 에너지 낮음. 열 1~3은 기분 좋지 않음, 열 4~6은 기분 좋음.

| | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| 1 | 격분한 | 스트레스 받는 | 충격받은 | 놀란 | 흥겨운 | 황홀한 |
| 2 | 화가 치밀어 오른 | 화난 | 안절부절 못하는 | 기운이 넘치는 | 낙관적인 | 흥분한 |
| 3 | 불쾌한 | 근심하는 | 마음이 불편한 | 유쾌한 | 희망찬 | 더없이 행복한 |
| 4 | 역겨운 | 의욕 없는 | 냉담한 | 속 편한 | 자족하는 | 충만한 |
| 5 | 비참한 | 쓸쓸한 | 피곤한 | 여유로운 | 편안한 | 안정적인 |
| 6 | 절망한 | 고독한 | 진이 빠진 | 나른한 | 고요한 | 안온한 |

- 사분면: 상좌 에너지↑·불쾌, 상우 에너지↑·유쾌, 하좌 에너지↓·불쾌, 하우 에너지↓·유쾌
- 색상은 `docs/design-tokens.md` 참고
- 셀 텍스트는 줄바꿈 포함(예: "화가 / 치밀어 오른"). 시안 기준 표기이며 일부 단어는 시안 글자가 작아 오타 가능성이 있으니 확인한다

## 5. 데이터 모델 초안 (Supabase / PostgreSQL)

개인정보 비식별 방식이 확정되기 전까지는 개인 식별 정보를 최소로 저장한다. 테이블명은 다른 프로젝트와 같은 DB를 쓸 경우를 대비해 `mm_` 접두사를 쓴다.

```
mm_sessions
  id uuid pk, created_at, completed_at
  face_consent boolean
  ui_type text            -- "type2"
  image_count int
  -- 참여자 정보 (비식별 정책 확정 후 컬럼 조정)
  participant_name text, birth_date text, gender text, job text, region text

mm_mood_checks
  id, session_id fk, phase text ("pre" | "post")
  row int, col int, emotion text, quadrant text

mm_image_responses
  id, session_id fk, image_id text, order_index int
  valence smallint (1-7), arousal smallint (1-7)
  response_ms int, responded_at
```

- 익명 인증(`signInAnonymously`)으로 세션 소유자를 구분하고, RLS는 "본인 세션의 INSERT / SELECT만 허용"으로 시작한다
- 클라이언트에서 UPDATE, DELETE는 허용하지 않는다 (연구 데이터 보존)
- 임시로 Supabase 없이 개발할 수 있도록 저장 계층을 `src/lib/storage`의 인터페이스로 분리하고 로컬(메모리) 구현을 먼저 둔다

## 6. 백엔드와 배포 (결정 대기)

- 이미 Supabase 무료 프로젝트 2개가 있다. 무료 플랜은 활성 프로젝트 수가 제한되므로 새로 만들 수 없을 가능성이 높다 (대시보드에서 확인)
  - A. 기존 프로젝트 하나에 `mm_` 테이블로 추가 (무료, 가장 빠름). 다른 서비스와 데이터와 RLS가 섞이는 점에 주의
  - B. 사용하지 않는 프로젝트를 삭제하거나 일시중지하고 새 프로젝트 생성 (분리 깔끔)
  - C. Firebase(Spark 무료) 등 다른 서비스. 정적 export와 호환되나 스키마 설계를 다시 해야 한다
- 무료 프로젝트는 비활성 시 일시중지될 수 있다. 청소년 개인정보와 얼굴 영상을 다루는 운영 단계에서는 기관 승인 인프라나 유료 플랜을 검토한다
- 배포: Vercel로 확정. 정적 export(`output: "export"`) 결과를 배포한다. 무료(Hobby) 플랜은 비상업·개인용 조건이므로, 발주처 납품 단계에서는 약관 확인이나 Pro 전환을 검토한다. `netlify.toml`은 삭제했다

## 8. 작업 백로그 (이슈 단위)

1. 프로젝트 초기화 (완료, PR 대기)
2. 공통 컴포넌트: Button, AppHeader, StepIndicator, TextField, Select
3. 스플래시 3단계 화면
4. 정보 입력 화면 + 검증
5. 카메라 동의 화면
6. 감정 격자 컴포넌트 + 사전·사후 무드미터 화면
7. 세션 상태 관리 (Zustand) + 저장 계층 인터페이스
8. 본조사 화면: 7단계 얼굴 척도 컴포넌트, 진행률, 이미지 로딩, 응답 시간 기록
9. 준비, 완료, 로딩 화면
10. 결과지 화면 + 공유, 이미지 저장
11. Supabase 연동 (스키마, 익명 인증, RLS)
12. PWA 마무리 (아이콘 교체, 오프라인 안내, iOS 홈 화면 스플래시)
13. 배포 설정 (Vercel 프로젝트 연결, 환경 변수 등록)
